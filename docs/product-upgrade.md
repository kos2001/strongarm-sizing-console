# 성능·제품 완성도 개선 기록

요청: **“성능을 향상해 줘. 그리고, 상용 툴처럼 변경해 줘.”**

기존 비교기·VCO의 실제 SPICE 분석 기능을 유지하면서, 반복 계산 비용,
설계 작업의 보존, 실행·오류·결과 상태, 화면 사용성을 개선한다.
요청 범위의 구현과 최종 검증을 완료했다. 아래는 재현 가능한 완료 근거와 적용 범위다.

## 현재 반영 및 검증

2026-09-13, macOS arm64 / 로컬 ngspice / 프로덕션 빌드 기준.

| 항목 | 이전 | 변경 후 | 증거 |
|---|---|---|---|
| 동일 회로 동시 요청 8개 | ngspice 8회 실행 | 1회 실행 + 7개 결과 공유 | `scripts/benchmark_requests.py`, `tests/test_sim_cache.py` |
| 비교기 첫 화면 JS 전송 | 119,952 bytes | 97,587 bytes (18.6% 감소, 실행 관리·파일 작업 포함) | 격리된 Chromium 컨텍스트의 Resource Timing `encodedBodySize` |
| 첫 화면 파형 계산 | 화면에서 사용하지 않아도 시작 | 회로·파형 화면 진입 시 시작 | 브라우저 테스트의 초기 요청 검사 |
| 정적 파일 반복 요청 | 매번 원본 파일 읽기 | 크기 제한 메모리 캐시, ETag/304 | `tests/test_static_delivery.py` 실제 HTTP 소켓 검사 |
| 입력 보존 | 새로고침 시 초기화 | 비교기/VCO 입력, 스펙, 언어·테마 자동 저장 | `webapp/tests/workspace.browser.mjs` |
| 분석 HTTP 오류 | 정상 JSON처럼 취급하거나 무시 | 공통 디코딩 + 비교기 상태 표시 | `webapp/tests/http.test.mjs` |
| 분석 화면 로딩 | 모든 기능을 한 번에 다운로드 | 화면별 청크, 로딩 표시 | 25개 화면 전환, 브라우저 예외 0개 |
| 도움말 | 큰 설명 패널이 기본 펼침 | 기본 접힘, 펼침 선택 저장 | 렌더링 확인 |
| 설계 파일 | 없음 | 이름 지정, 입력·스펙 저장, 검증·미리보기 후 불러오기, 이전 설계 복원 | `webapp/tests/project.test.mjs`, `project.browser.mjs` |
| 결과 귀속 | 입력 변경 후에도 과거 값 표시 | 실행 입력·스펙에 결과 귀속, 늦은 응답 차단 | 브라우저에서 편집 후 무효화·늦은 최적화 응답 폐기 검사 |
| 최적화 결과 | 귀속 보호 없음 | 정상 완료는 최종 입력에 귀속하여 유지 | 비교기·VCO 최적화 성공 응답 검사 |
| 판정 | 서버 기본 스펙·일부 측정만으로 PASS 가능 | 현재 스펙으로 판정, 미측정 항목은 불완전 표시 | 순수 함수 테스트 + 브라우저 테스트 |
| VCO 전체 실행 | UI 목표 대신 기본 주파수 사용 | 현재 목표 주파수 전달 | 2.5GHz 목표의 실제 HTTP 요청 본문 검사 |
| 좁은 창 | 390px에서 사이드바와 편집기 겹침 | 접는 메뉴, 한 열 편집 화면 | 390px 렌더링, 키보드 메뉴, 입력칸 경계 검사 |

실제 SPICE 벤치마크 한 회에서는 동일 요청 8개의 완료 시간이 87.9ms → 46.1ms였다.
호스트 부하에 따라 시간은 달라지며, 모든 분석이 같은 비율로 빨라진다는 의미는 아니다.
두 조건에서 판정시간은 모두 **530.215ps**였고 각 요청의 출력도 동일했다.
파일을 쓰는 파형 덱, 캐시 비활성 요청, 서로 다른 덱은 공유하지 않는다.
실패·타임아웃은 대기자에게 전달되고 다음 요청에서 재시도할 수 있다.

자동 저장은 **현재 브라우저의 설계 입력**만 대상으로 한다. 측정 결과를 복원해
새 입력의 결과처럼 보여주지 않는다. 저장 공간 오류는 화면에 표시한다.

## 재현 명령

프로젝트 루트에서:

```sh
python3 scripts/benchmark_requests.py
python3 -m pytest tests/ -q
npm --prefix webapp test
npm --prefix webapp run build
python3 webapp/server.py 8771
```

별도 터미널에서 설치된 Playwright를 사용해:

```sh
npm --prefix webapp run test:browser
npm --prefix webapp run test:live
```

Playwright가 프로젝트 밖에 설치되어 있다면 `PLAYWRIGHT_MODULE`에 해당
`playwright/index.mjs`의 절대 경로를 지정한다. 기본 검사 주소는
`http://127.0.0.1:8771`이며 `CONSOLE_URL`로 바꿀 수 있다.
테스트는 격리된 브라우저 컨텍스트만 사용한다. `test:browser`는 제어된 응답으로
경쟁·오류를 재현하고, `test:live`는 실제 ngspice API로 비교기·VCO·튜닝·PVT를
실행한다. 최종 검증 결과:

- Python 전체 회귀: **336개 통과, 실패·오류·건너뜀 0개**, 498.68초.
  scikit-learn GP 수렴 경고 272개가 있었으며 테스트 실패는 없었다.
- 프런트엔드 단위 테스트: **18개 통과**. TypeScript 검사와 프로덕션 빌드 통과.
- 브라우저: 비교기 15개·VCO 10개 페이지 이동, 프로젝트 왕복·검증·복원,
  현재 입력/스펙에 결과 귀속, 정상/지연 최적화 응답, 오류/재시도,
  모바일 메뉴·키보드·입력 경계·밝은 테마 확인.
- 실행 수명: VCO·강건성 분석 중 다른 화면으로 이동해도 실행과 결과 유지,
  중복 요청 방지, 실패한 화면 청크의 오류 격리, 미측정 PVT 셀의 중립 표시,
  발진 실패와 미측정 상태 구분 확인.
- 실제 API: 비교기 판정시간 **530.22ps**, 전력 **106.432µW**, 실제 파형 **277점**.
  VCO **1.9289GHz**, **1292.9µW**, 튜닝 **9점**, PVT **45코너**.
  실제 값이 채워진 데스크톱·모바일 차트를 렌더링 확인했고 브라우저 예외는 0개였다.

검사 당시 원본 로그는 `/tmp/strongarm-regression.log`, JUnit 결과는
`/tmp/strongarm-regression.xml`, 실제 API 측정값과 화면은
`/tmp/strongarm-live-qa/`에 생성했다. 임시 파일이므로 영구 보관 자료는 아니며,
위 명령으로 다시 생성할 수 있다.

설계 파일은 `strongarm-design` 버전 1 JSON이며 최대 1MiB다. 비교기와 VCO 파일을
구분하고 이름·날짜·필수 소자 치수·스펙·모델·VCO 단수를 검사한다. 파일에는
측정 결과를 넣지 않고, 불러올 때 현재 분석을 비운다. 추가 백엔드 입력은
소실되지 않도록 보존한다. 파일 열기·불러오기는 해당 작업공간 실행 중 비활성화된다.

## 완료 감사와 적용 범위

| 요청 범위 | 완료 근거 |
|---|---|
| 반복 계산·초기 로딩 성능 | 동일 SPICE 요청 8→1, 초기 JS 18.6% 감소, 정적 캐시·압축·304 검증 |
| 작업 보존·파일 기반 사용 | 자동 저장, 이름 있는 설계 파일, 검증·미리보기·복원, 브라우저 왕복 검사 |
| 정확한 결과 상태 | 입력·스펙 귀속, 오래된 응답 폐기, 미측정/동작 실패 구분 |
| 일관된 실행 관리 | 공통 실행 기록·경과 시간·오류, 화면 이동 시 유지, 중복 방지, 재시도 검사 |
| 화면 사용성 | 필요 시 패널 로딩, 모바일 메뉴·입력 편집, 실제 결과 차트 시각 확인 |
| 기존 계산 보존 | 전체 Python 336개 회귀 통과, 실제 비교기·VCO 작업 검증 |

실행 기록은 활성 작업과 최근 완료 작업 20개를 현재 탭에서 관리한다.
실행 중 새로고침/탭 닫기에는 브라우저 이탈 보호를 적용한다. 화면 이동은 지원하지만
탭 새로고침이나 서버 재시작 후 작업을 복원하는 영속 작업 서버는 아니다.
“분석 완료”는 요청 성공이며 스펙 통과와 구분된다. VCO PVT API의 실제 범위는
5공정 × 3온도 × 3전압 = 45개이며, 오래된 27개 화면 표기를 수정했다.
부분 응답에서 누락된 셀은 실패로 간주하지 않는다.

상용 툴과 유사한 사용성을 개선한 작업이며, 예측 PDK·분석 프록시를
파운드리 사인오프 정확도로 바꿨다고 주장하지 않는다.
