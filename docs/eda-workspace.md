# EDA 작업공간 통합 및 실제 물리 설계 기록

요청: 페이지의 중복 내용을 합치고 EDA 도구 형태로 변경한다.
추가 요청: `ppa-eda-agent` 구현을 참고해 레이아웃에 실제 내용을 반영한다.

## 통합 구조

| 작업공간 | 비교기 | VCO |
|---|---|---|
| 설계 편집 | 소자·목표·회로도·파형·공칭 측정 | 소자·회로도·발진·튜닝·공칭 측정 |
| 특성 분석 | 입력 해상도, 메타안정성, 노이즈/BER, 최대 클럭 | 위상잡음, 전원 푸싱 |
| 최적화 | 자동 탐색, 민감도, 파레토 | 자동 사이징, 파레토 |
| 변동성 검증 | PVT, 오프셋 분포, 수율, WiCkeD | PVT, 수율/강건성 |
| 구현·검증 | GDS, 실제 P&R 기록, 전체 흐름 | GDS, 실제 P&R 기록, 전체 흐름 |

기존 15개·10개 최상위 페이지를 각각 5개 작업공간으로 통합했다.
서로 다른 알고리즘은 내부 탭으로 보존한다. 설계 편집 화면은 중앙 회로도·결과,
오른쪽 단일 속성 편집기, 아래쪽 실행 출력으로 구성한다. 좁은 화면에서는
세로 배치와 접이식 탐색기를 사용한다. 세부 탭은 방향키·Home·End로 이동한다.

설계 입력/회로 페이지를 물리적으로 합쳤고 VCO의 중복 회로 미리보기를 제거했다.
스펙 상태 요약은 편집 화면에서 수치 게이지를 다시 반복하지 않는다.
입력 해상도 실행 한 번으로 메타안정성과 BER 상세 탭까지 채워지므로,
상세 내용을 보기 위해 같은 측정을 다시 실행할 필요가 없다.
프로빗, 최대 클럭, 오프셋 샘플링은 별도 측정 방식이므로 유지한다.

## ppa-eda-agent 반영 범위

참조한 구현:

- `dashboard/src/components/EdaShell.tsx`, `EdaShell.css`: 조밀한 패널,
  실제 도구 상태와 실행 출력을 연결하는 UI 원칙.
- `dashboard/src/components/LayoutView.tsx`: DEF/LEF의 실제 셀 좌표와
  배선 세그먼트, 금속층별 표시, Y축 변환.
- `server/index.mjs`의 `lightCase`/`candidateDetail`: 목록과 무거운 형상 데이터 분리.
- `dashboard/src/api/referenceDb.ts`: 후보별 PPA 및 검증 데이터 구조.

**구현·검증 → 레이아웃 → ppa-eda-agent · 실제 P&R**에서 실행 파일과 후보를
선택하면 참조 저장소의 실제 기록을 읽는다. 임의의 데모 좌표는 만들지 않는다.
선택한 설계·날짜·후보·PDK, 실제 셀/넷, 레이어 전환, 확대·축소, 면적·전력,
검사별 위반 수를 표시한다. 형상이 없는 후보는 빈 그림으로 통과시키지 않고
기록 없음을 표시하며, 누락된 검사는 미검증이다.

이 기록은 선택한 참조 설계의 결과다. `counter4`의 배선을 현재 편집한
StrongARM/VCO의 배선이라고 표시하지 않는다. 현재 설계 탭은 실제 입력으로
생성된 GDS 초안, 레이어별 형상, 크기, 파일 경로, 간단한 폭/간격 검사 결과를
표시한다. 이 초안의 LVS·배선 연결은 검증되지 않았다. 신규 P&R 실행이나
파운드리 사인오프 완료를 추가했다고 주장하지 않는다.

백엔드는 기본적으로 형제 저장소 `ppa-eda-agent/reference-db/cases`를 읽는다.
다른 위치는 서버 시작 시 `PPA_EDA_ROOT`로 지정한다. 읽기 전용이며 외부
저장소 코드 실행·파일 변경·추가 시뮬레이션을 하지 않는다. 파일 목록은
이름/크기만 전송하고 후보 형상은 선택했을 때만 읽는다. 파일 경로 이탈,
파일 심볼릭 링크 및 64MiB 초과 파일을 거절한다.

## 검증

- TypeScript 및 프로덕션 빌드 통과.
- 프런트엔드 단위 18개, 참조 로더·정적 HTTP·gzip 회귀 26개 통과.
- 기존 설계 저장·파일 왕복·잘못된 파일 거부·늦은 최적화 응답·실행 유지·모바일 검사 통과.
- 작업공간별 전체 세부 탭 접근, 단일 편집기, 공통 프로젝트 도구 모음,
  키보드 탭, 1회 측정으로 해상도/메타안정성/BER 결과 재사용 확인.
- 실제 ngspice: 비교기 530.22ps / 106.432µW / 파형 277점,
  VCO 1.9289GHz / 1292.9µW / 튜닝 9점 / PVT 45코너 확인.
- 실제 참조 `counter4__2026-08-21.json`, `sweep-util-25`: 셀 27개·넷 25개,
  배선 표시·레이어 숨김·확대·전체 보기 확인. 형상이 없는 다른 실행과
  20개 이상의 개별 검증 결과가 있는 실행도 확인.
- 현재 비교기의 실제 GDS 생성 및 결과 뷰 확인. 데스크톱과 모바일 차트를
  렌더링 확인했으며 브라우저 예외 0개.

프로젝트 루트에서 서버를 시작한 뒤:

```sh
npm --prefix webapp test
npm --prefix webapp run build
python3 -m pytest tests/test_physical_reference.py tests/test_static_delivery.py tests/test_http_gzip.py -q
CONSOLE_URL=http://127.0.0.1:8770 npm --prefix webapp run test:browser
CONSOLE_URL=http://127.0.0.1:8770 npm --prefix webapp run test:live
CONSOLE_URL=http://127.0.0.1:8770 npm --prefix webapp run test:physical
```

브라우저 검사는 Playwright가 필요하며 외부 설치는 `PLAYWRIGHT_MODULE`로 지정한다.
`test:physical`은 명시한 실제 참조 파일이 있는 환경의 통합 검사다.
